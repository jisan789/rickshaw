Building Zero-Asset Procedural 3D Surface Games

A universal engineering manual on designing high-framerate 3D geometric surface games without external 3D model files (.gltf / .obj), achieving sustained 60–120 FPS on mobile browsers through mathematical procedural generation, single-draw-call batching, and zero-allocation loops.

1. The Zero-Asset Philosophy

Most 3D web games fail in production due to heavy network payloads. Loading 40MB of 3D meshes and 2K textures causes massive time-to-interactive delays, memory spikes on mobile GPUs, and sudden garbage collection stutters.

❌ Asset-Heavy Model

• Downloads .glb / .gltf / .bin files
• Uncompresses 1024x1024 PNG/JPG textures
• Separate meshes = 80–200 GPU draw calls
• Heavy VRAM usage causes crashes on budget phones

✅ Procedural Mathematical Model

• 0 external 3D files (entire game under 1MB)
• Surfaces & meshes calculated directly in JS memory
• Merged into a single BufferGeometry (1–5 draw calls)
• Boots instantly on 3G, runs smoothly on any device

4. Mathematical Foundations of 3D Surfaces

All 3D surfaces in procedural games come down to calculating arrays of vertices $(x, y, z)$ and connecting them with triangles.

A. Heightmap Surfaces (Noise / Waves)

A grid of size $W \times D$ where height $y$ is computed by a mathematical formula or noise function: 

function computeHeight(x, z, time = 0) {
  // Multi-octave wave superposition (Perlin / Simplex approximation)
  const wave1 = Math.sin(x * 0.15 + time) * Math.cos(z * 0.15);
  const wave2 = Math.sin(x * 0.3 - time * 0.5) * 0.5;
  return (wave1 + wave2) * 1.8;
}

B. Surface Normal Vectors for Real-Time Lighting

For light to interact with a procedural surface, every vertex needs a surface normal vector $\vec{N}$. Instead of expensive trigonometry, calculate the finite difference between adjacent vertices: 

// Finite difference normal calculation:
const eps = 0.1;
const hL = computeHeight(x - eps, z);
const hR = computeHeight(x + eps, z);
const hD = computeHeight(x, z - eps);
const hU = computeHeight(x, z + eps);

// Normal = cross product of tangents
const normal = new THREE.Vector3(hL - hR, 2.0 * eps, hD - hU).normalize();

5. The Procedural Geometry Builder Pattern

Instead of creating dozens of separate THREE.Mesh instances, modern high-performance engines use a Geometry Builder that pushes vertices, normals, and colors into contiguous native Float32Array buffers: 

class ProceduralMeshBuilder {
  constructor() {
    this.positions = [];
    this.normals = [];
    this.colors = [];
    this.indices = [];
    this.count = 0;
  }

  addQuad(p1, p2, p3, p4, normal, rgbColor) {
    const base = this.count;
    // Push 4 vertices
    this.positions.push(...p1, ...p2, ...p3, ...p4);
    for (let i = 0; i < 4; i++) {
      this.normals.push(...normal);
      this.colors.push(...rgbColor);
    }
    // 2 Triangles for 1 Quad
    this.indices.push(base, base + 1, base + 2, base, base + 2, base + 3);
    this.count += 4;
  }

  build() {
    const geo = new THREE.BufferGeometry();
    geo.setAttribute('position', new THREE.Float32BufferAttribute(this.positions, 3));
    geo.setAttribute('normal', new THREE.Float32BufferAttribute(this.normals, 3));
    geo.setAttribute('color', new THREE.Float32BufferAttribute(this.colors, 3));
    geo.setIndex(this.indices);
    return geo;
  }
}

6. Single-Draw-Call Batching

The golden rule of 3D web performance: Every draw call has CPU driver overhead.

🏆 The 1-Draw-Call Rule
By utilizing Vertex Colors (material.vertexColors = true) and merging all static obstacles, curbs, road surfaces, and buildings into a single BufferGeometry, the entire game world renders in exactly 1 draw call. 
// One unified material for all surfaces:
const universalMaterial = new THREE.MeshLambertMaterial({
  vertexColors: true, // Colors come from vertex attributes, eliminating texture lookups!
  roughness: 0.8
});

// All world objects exist in 1 single mesh:
const worldMesh = new THREE.Mesh(builder.build(), universalMaterial);
scene.add(worldMesh);

7. Generator Time-Slicing (Eliminating Frame Drops)

When generating infinite or chunked terrain as the player moves, calculating hundreds of math coordinates in a single frame will cause frame drops.

Use JavaScript Generators (function* + yield) to budget chunk generation to a maximum of 2–3 milliseconds per frame: 

class ChunkStreamer {
  *createChunkRoutine(chunkX, chunkZ) {
    const builder = new ProceduralMeshBuilder();

    // Step 1: Generate roadbed
    buildRoadbed(builder, chunkX, chunkZ);
    yield; // Pause and return control to the browser

    // Step 2: Generate roadside structures
    buildBuildings(builder, chunkX, chunkZ);
    yield; // Pause

    // Step 3: Finish and upload buffer to GPU
    return new THREE.Mesh(builder.build(), material);
  }

  tickSlice(timeBudgetMs = 2.5) {
    if (!this.activeJob) return;
    const start = performance.now();
    while (performance.now() - start < timeBudgetMs) {
      const res = this.activeJob.next();
      if (res.done) {
        scene.add(res.value);
        this.activeJob = null;
        break;
      }
    }
  }
}

8. The Zero-Allocation Render Loop (GC Elimination)

⚠️ The Garbage Collection Hazard
If you write const pos = new THREE.Vector3() inside your requestAnimationFrame loop, you are creating 60 new objects every second. After a few seconds, the browser will pause execution for 20ms–50ms to run Garbage Collection, causing noticeable stutter.

The Rule: Pre-allocate reusable scratch vectors outside loops: 

// PRE-ALLOCATED SCRATCHPAD (Created ONCE at initialization)
const _v1 = new THREE.Vector3();
const _v2 = new THREE.Vector3();
const _matrix = new THREE.Matrix4();

function gameLoop(dt) {
  // ❌ NEVER DO THIS: const temp = player.pos.clone().add(offset);

  // ✅ DO THIS (0 Byte memory allocation):
  _v1.copy(player.pos).add(offset);
  camera.position.lerp(_v1, dt * 5);
  camera.lookAt(player.pos);
}

9. Hybrid 3D Canvas + DOM UI Experience

Do not render text or complex instrument panels directly in 3D canvas textures unless necessary. HTML5 and CSS3 are already hardware-accelerated, support responsive scaling, and provide pixel-perfect typography.

Architecture of the Hybrid UI:

1. Layer 0 (Bottom): Fullscreen WebGL Canvas.
2. Layer 1 (Top Overlay): Fixed HTML container with pointer-events: none.
3. Layer 2 (Interactive Controls): Buttons and inputs with pointer-events: auto.
4. Zero-Image Vector Styling: Inlined SVG Data-URIs inside CSS for custom borders and badges. 

/* Ultra-fast glassmorphism HUD */
.game-hud {
  position: fixed;
  inset: 0;
  pointer-events: none; /* Let clicks pass through to 3D canvas */
  z-index: 10;
  font-family: 'Inter', sans-serif;
}

.hud-interactive {
  pointer-events: auto; /* Re-enable clicks for specific buttons */
}

10. 3D-to-2D Screen Space Projection

To anchor nameplates, target reticles, damage indicators, or chat bubbles directly over 3D vehicles or enemies: 

const _projectVector = new THREE.Vector3();

function attachBadgeOver3DObject(domBadgeElement, object3DPosition, camera) {
  _projectVector.copy(object3DPosition);
  _projectVector.y += 2.0; // Elevation above the object
  
  // Project from 3D World Space to Normalized Device Coordinates (-1.0 to +1.0)
  _projectVector.project(camera);

  // Check if object is in front of the camera (z < 1)
  if (_projectVector.z >= -1 && _projectVector.z < 1) {
    const screenX = (_projectVector.x * 0.5 + 0.5) * window.innerWidth;
    const screenY = (-(_projectVector.y * 0.5) + 0.5) * window.innerHeight;

    domBadgeElement.style.display = 'block';
    domBadgeElement.style.transform = `translate(-50%, -100%) translate(${Math.round(screenX)}px, ${Math.round(screenY)}px)`;
  } else {
    domBadgeElement.style.display = 'none'; // Culled behind camera
  }
}
